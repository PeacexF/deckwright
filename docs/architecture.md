# Architecture

```text
.claude-plugin/          plugin.json, marketplace.json (install from this repo)
skills/deckwright/       SKILL.md (the workflow), references/api.md (deck script API)
scripts/                 command-line entry points
  build.mjs              deck.mjs -> PPTX -> render -> QA
  new.mjs                start deck-output/<slug>/ (never overwrites)
  qa.mjs                 QA any .pptx
  commons.mjs            Wikimedia Commons images + credits.json
  doctor.mjs             check tools, packages, fonts
scripts/lib/             the library — deck folders never contain engine code
tests/unit, tests/e2e    node:test suites
```

## A deck folder

```text
deck-output/<slug>/
  sources.md raw_data.md report.md   research stages, written by Claude
  deck.mjs                            slide list: content and layout choices only
  img/ + img/credits.json             pictures and their credits
  <Title>.pptx                        the deliverable
  build/manifest.json                 what layout placed where (input to QA)
  qa/report.md, sheet.jpg, png/       QA results
```

`deck.mjs` exports `(deck) => { … }`. It imports nothing: `build.mjs` passes the library in, so there is no engine to copy and nothing to drift.

## Build pipeline

1. **Layout** (`deck.mjs` → `lib/deck.mjs`). Each slide gets chrome from the theme (free design) or the template, then the deck script places components into boxes. Components measure themselves with `lib/text.mjs` before placement, so overflow, too-long words, sizes below a role's minimum, content in a template's reserved zones, missing notes, uncredited images and slide-count limits are reported as build problems with slide numbers.
2. **Write.** Free design: PptxGenJS. Template: `lib/template.mjs` copies the template, fixes what it can (`.potx` content type, font names with stray whitespace), adds seed slides built from the title-only layout, fills them with pptx-automizer (title into the placeholder, content generated by PptxGenJS), and writes speaker notes into the package.
3. **Render** (`lib/render.mjs`). LibreOffice headless with an isolated profile → PDF → PNG pages → contact sheet.
4. **QA** (`lib/qa.mjs`, `lib/pptx.mjs`). Reads text shapes from the PPTX XML (placeholder boxes resolved through layout and master), reads every rendered word's position from `pdftotext -bbox`, aligns the two, and checks overflow, mid-word breaks, collisions, reserved zones, off-slide text, tiny text, fonts (requested, installed, actually embedded), notes and empty placeholders.

## Text measurement

LibreOffice is the reference renderer, so measurement models LibreOffice:

- line breaks: greedy, at spaces and after in-word hyphens and dashes; widths from the real font files via fontkit;
- line height: 1.2 × size × line spacing for every font (measured on ten fonts whose own metrics range from 1.13 to 1.30);
- fonts: one fontconfig setup (`fontconfigFile()` in `lib/tools.mjs`) for both LibreOffice and `fc-match`. Without it, headless LibreOffice on macOS sees only its bundled fonts, and with system fonts but no fallback rules it substitutes arbitrary families.

Predicted heights are verified to stay within a few hundredths of an inch of the render, on the conservative side.

## Templates

`loadTemplate()` profiles the template:

- layouts: the title layout (cover, thank-you) and the title-only layout (content);
- the title box, size and font from the layout and master title style;
- reserved zones: pictures (logos), the slide number and rules on the master and layout;
- the safe area: below the title, above wide zones (rules); corner zones (a big slide number) cap the body, and the strip beside them holds the sources line;
- fonts: the master body style's font if installed, else the same fallback the template's own placeholders render in;
- palette from the theme colours.
